# Exam-Kraft integration audit

## Findings and fixes

| Workflow | Finding | Fix |
| --- | --- | --- |
| Student login and navigation | Login defaulted to the staff workspace. The staff shell checked authentication without checking the role. Student exit actions also pointed into staff routes. | Students land on **My Examinations** at `/student`. Login preserves role-compatible deep links. Route guards protect the staff and candidate route groups. The staff shell also checks the role before rendering navigation. Student back and exit actions return to the portal. |
| Candidate discovery and lobby | The lobby called the staff preview endpoint, received a 403, and rendered generic examination values. The start endpoint did not apply the same publication and assignment rules as the lobby requires. | Candidate endpoints at `/api/v1/student/examinations/` and `/api/v1/student/examinations/<id>/` return examination metadata. Discovery, lobby access, and attempt start use the candidate's organization and match direct, active batch, or active centre assignments. Published exams with no assignment rows remain open to candidates in the same organization for compatibility with existing exams. The staff preview keeps its existing permissions. |
| Exam setup | The examination form sent time-zone-free timestamps. Exams created from a selected paper rendered zero total marks unless the API caller supplied marks. Assignment feedback counted batch and centre records as individual candidates. | The form sends ISO timestamps with an explicit offset. The API defaults omitted marks to the sum of marks on the selected paper. Assignment feedback describes the records created. |
| Question delivery and LaTeX | Question-bank preview displayed formula source. The CBT renderer performed string substitution and left common superscripts and subscripts as raw notation. An exam with empty sections could suppress paper questions. | Question authoring and CBT share a MathML renderer for inline and display math, fractions, roots, scripts, and common symbols. Empty sections are skipped, with paper fallback when the exam has zero linked section questions. The renderer handles a subset of LaTeX. |
| CBT responses, timer, and navigation | Clearing a response could send the old option or number. The local cache was shared across candidates for the same exam. A zero remaining time could become an hour, timer throttling could cause drift, and submission could get ahead of an answer save. The CBT header used hard-coded candidate data. | Clear sends an empty answer. Pending saves are scoped by attempt and retried before manual submission. The timer uses server remaining time and elapsed time between heartbeats. Concurrent starts for the same candidate serialize on the user row on databases supporting row locks. The CBT header uses the signed-in profile and an enrolled roll number. Finish uses the returned attempt ID for the report and redirects direct visits without a submission receipt to the candidate portal. |
| CSV and candidate roster | The roster had no centre filter and could display details from the wrong enrollment when the candidate belonged to multiple batches. CSV imports could add a centre without refreshing the available filters. | The roster sends batch and centre filters together and displays the matching active enrollment. CSV upload refreshes centre and batch metadata. The sample CSV and upload guidance document the optional Password column for candidates who need to sign in. |
| Local launch and Django discovery | Vite defaulted to 3000. The requested root-level Django command discovered the top-level mock-server package instead of the backend Django suite. | Vite defaults to 5173 and proxies the API to the IPv4 Django listener on port 8000. Bare `manage.py test` discovers from the backend directory regardless of the caller's working directory. |

## Verification

| Check | Result | Evidence |
| --- | --- | --- |
| `python backend/manage.py test` from the repository root | Passed | 84 tests, zero failures and zero errors. The workspace Python 3.9 environment lacked Django, so this run used the installed Python 3.12 and cached packages. |
| Staff and candidate API workflow | Passed | The new Django integration test creates a batch and centre, uploads a multipart CSV, verifies roster fields for a candidate with two enrollments, creates a paper and MCQ with answer options, assigns batch and centre, and publishes the exam. Candidate JWT login, lobby, start, heartbeat, answer save, clear, recovery, and submission return successful responses. The test also verifies draft and unassigned rejection, assignment retry behavior, the expected 403 from the staff preview, and exclusion of answer keys from delivery. Existing Django coverage checks raw CSV and rollback. |
| Frontend production build | Passed | `cd frontend && npm run build` completed TypeScript checking and Vite bundling. |
| React static markup and landing paths | Passed | A local Node smoke check rendered the React math component and asserted inline and display MathML, a fraction, superscript, subscript, square root, and malformed-expression fallback. It also asserted the student and staff landing paths. |
| Live browser and HTTP | Blocked in this session | Vite failed to listen on 5173 with `EPERM`. Django failed to bind 8000 with `[Errno 1] Operation not permitted`. Loopback curl also reported `Operation not permitted`. Browser clicks, actual timer rendering, camera behavior, and browser console/network traces remain unverified. API test-client results and static markup checks exercise those contracts without a listening socket. |

To reproduce the remaining browser checks on a host with local networking, start Django on 8000 and run `npm run dev` in `frontend`. In a disposable organization, import a candidate CSV with a known password, filter the roster by batch and centre, author a formula question and its options, attach the paper to an exam, assign the batch or centre, and publish. In a separate browser session, sign in as the imported candidate, direct-load a staff route, then open the exam from **My Examinations**. Confirm the lobby displays the authored exam, use **Save & Next** and **Clear Response**, reload the CBT page to verify saved state, and submit. Verify the finish page displays the returned attempt ID. A performance report can remain unavailable until results are published and the examination window is closed.
